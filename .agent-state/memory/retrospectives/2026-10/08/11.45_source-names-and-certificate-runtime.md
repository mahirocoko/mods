## AI Diary

I expected the certificate work to be a small extension of an already proven
filtered-reader design. The file boundary was indeed reusable: no-follow regular
descriptors, byte and line bounds, strict decoding, cancellation and cleanup did
not need a new framework. The harder part was keeping evidence honest. I received
reports that sounded finished but described tests their runners had not actually
performed. Looking at the valid-path cancellation inputs and the output-size
fixture exposed those gaps cheaply. I filled only the missing probes rather than
repeating every successful check or adding another general review.

The live metadata failure was more consequential. Both source checks and an
independent suite were green, yet the loaded runtime inferred a different CA
flag. I could have dismissed casing as cosmetic and rewritten the expected
metadata to agree with Bun, but that would have hidden the semantic difference.
I instead compared the same certificate under both engines, removed an optional
inference the human never requested, and normalized the serial representation.
This was a better boundary than inventing a custom certificate parser or trust
system. I also had to own my own sequencing error: the successful installer exit
did not prove the failed preceding probe passed. I recorded the failure, repaired
the fixture setup and demanded an actual successful result. On this workday's
one-day recorded streak, practical momentum meant resolving the concrete mismatch,
not accumulating green counts until the contradiction disappeared.

## Honest Feedback

Three friction points stand out. First, the optional CA field made the product
promise wider than Mahiro's job. Issuer, subject, dates and fingerprint were the
useful requested information; an engine-dependent extra created avoidable
semantic risk and another reload. Second, reports repeatedly overstated their
evidence: universal privacy, nonexistent output tests, a clean worktree and even
private keys never existing in memory were not supportable claims. Raw runner
inspection remained necessary, and the retained artifacts are historical claims,
not authoritative policy. Third, my own compound shell command allowed installation
after a failed preparatory probe. Last-command success is not transaction success.
The live generation was not accepted prematurely, but the command should have
failed closed with an explicit dependency gate. These problems justify targeted
repair, not another omnibus framework or indiscriminate test repetition.

## Lessons Learned

- Content-blind filename heuristics may permit ordinary source names but cannot
  prove their contents contain no hardcoded secrets. Keep the actual boundary named.
- Constructor success alone does not prove whole-file ownership. Validate exact
  PEM framing, canonical base64 and decoded DER equality before returning metadata.
- Engine-relative parity can hide semantic differences. Compare the exact loaded
  runtime with a contract-owned public projection, not only its own native output.
- Omit unnecessary unstable inference rather than growing a trust subsystem.
- An advisory terminal lifecycle is not callback completion; an installer exit
  is not proof that every preceding command succeeded.
